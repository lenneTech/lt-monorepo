# Migration guide 3.16.1 → 3.17.0

This template is consumed by copy. `lt fullstack update` does not sync `scripts/`, so nothing
below reaches an existing project on its own. Each section says what breaks if you adopt only
half of it.

---

## 1. The overrides guard: copy it together with its test

`scripts/check-overrides.mjs` is ported again from `@lenne.tech/nest-server`, now with three
changes that the starters' audit declarations rely on:

- **Several consumers per declaration.** An `auditConfig.unusableFixConsumers` entry may name
  several consumers joined with ` + `. The previous copy read `a@1 + b@2` as one consumer named
  `a@1 + b`, so the multi-consumer entries nest-server-starter 12.2.0 hoists into your workspace
  fail with `RE-TEST`.
- **Only edges to an affected version count.** A parent that pulls the fixed release is not a
  consumer of the vulnerability. nuxt-base-starter 2.33.4 lifts `glob` and `readdir-glob` onto
  minimatch 11.0.3, and the previous copy counted them anyway and failed the minimatch
  declaration for good.
- **Advisories that name no fix are looked up in the registry**, honouring `minimumReleaseAge`.

**Copy `scripts/check-overrides.mjs` and `scripts/check-overrides.test.ts` together.** With the
new guard and the old test, `test:scripts` goes red: 3 of the 61 old cases feed an advisory
without a fix offline and pass no `--packument-file`, which the registry lookup now requires.

## 2. The release tool is gone

The template no longer ships `commit-and-tag-version`, the `release`, `release:minor` and
`release:major` scripts, `.versionrc.json` or `scripts/check-wrapper-version.cjs`. The tool
pulled `dotgitignore@2.1.0 > minimatch@3.1.5` (GHSA-g3hv-75wg-m249), and no override can lift
that: dotgitignore calls `minimatch.makeRe()`, which minimatch 11 removed.

Your project still has the tool, and the declaration hoisted from nest-server-starter does not
name dotgitignore, so the guard from section 1 fails the entry with
`RE-TEST … dotgitignore@2.1.0 also pulls an affected package`. Choose one:

- **Drop the tool:** remove it from the root `devDependencies` together with the three scripts,
  then `pnpm install`. Then either
  - keep `.versionrc.json` and `scripts/check-wrapper-version.cjs`. Projects from 3.13.0 on
    carry a `scripts/check-wrapper-version.test.mjs` that reads both, and deleting them turns
    `test:scripts` red; or
  - copy the new `scripts/check-wrapper-version.test.mjs`, which needs neither, and delete
    both files.
- **Keep the tool:** add `dotgitignore@2.1.0` to the declaration and say in its comment why the
  path is acceptable (it compiles only your own `.gitignore` patterns, during a release).
  nuxt-base-starter's `migration-guides/2.33.4-glob-minimatch-majors.md`, step 3, has the
  full line.

Leave `brace-expansion@<1.1.21` in your `pnpm-workspace.yaml`. The template dropped its own
copy because its tree no longer contains the package; in your workspace the same key comes
from nest-server-starter, where a production path needs it.

## 3. Agent memory is ignored in the template

`.gitignore` gains `**/.claude/agent-memory`, because this repository is public and review
agents' notes do not belong in it. Nothing changes for an existing project. Whether a project
commits its agent memory is its own decision (lt-dev `managing-agent-memory`).
